# 実機動作検証チェックリスト

制定日：2026年8月11日
対象: PDF One（iOS 17.0+ / SwiftUI / `TARGETED_DEVICE_FAMILY: "1,2"`＝iPhone・iPad両対応）

> **これまでの動作確認はシミュレータのみ**（`HANDOFF.md`記載）。本チェックリストは実機での初回検証を前提に作成する。特にPDFKit/Vision/CoreTextによる重いレンダリング処理はシミュレータとメモリ・熱特性が大きく異なるため、実機検証が必須。
>
> **重要な設計上の懸念**: アプリコード（`PDF_OneApp.swift`）に`scenePhase`監視や`beginBackgroundTask`等のバックグラウンド延命処理が**一切実装されていない**。Office変換・OCR・圧縮など数秒〜数十秒かかる処理中にユーザーがホームに戻ると、iOSに処理を強制中断される可能性が高い。バックグラウンド遷移時の挙動確認を最優先項目とする。

## 0. 検証端末マトリクス

| 端末 | iOSバージョン | 優先度 | 理由 |
|---|---|---|---|
| iPhone SE（第3世代）またはiPhone 13/14無印 | 最新 / iOS 17.0（最低対応） | 高 | 最小メモリ構成でのメモリ圧迫・熱設計の下限確認 |
| iPhone 15 | 最新 | 高 | ユーザー指定端末 |
| iPhone 15 Pro | 最新 | 高 | ユーザー指定端末、A17 Pro・USB-C |
| iPhone 16 | 最新 | 高 | ユーザー指定端末 |
| iPhone 16 Pro | 最新 | 高 | ユーザー指定端末、最新チップでの基準測定 |
| iPad（無印、直近世代） | 最新 | 中 | `TARGETED_DEVICE_FAMILY`にiPadを含むため、レイアウト崩れ・マルチタスク影響を最低1台確認 |
| iOS 17.0系（最新未満の最小対応バージョン） | 17.0固定機 | 中 | 最新iOS以外での回帰確認（可能なら1台） |

- 各端末で**低ストレージ状態（空き容量1GB未満）**を模したテストも1回は実施すること。
- Wi-Fi/モバイル通信オフ（機内モード）でも全機能が動作すること（本アプリはオンデバイス処理のため通信不要が前提）を確認する。

## 1. メモリ（Instruments: Allocations / Leaks / VM Tracker）

| # | 項目 | 手順 | 合格基準 |
|---|---|---|---|
| 1-1 | Leaksでのメモリリーク検査 | Xcode Instruments「Leaks」テンプレートを起動し、全12機能（結合・画像PDF化・圧縮・ページ編集・PDF→JPG・分割・パスワード保護/解除・電子署名・OCR・透かし・Office変換両方向・設定のキャッシュ削除）を1回ずつ実行 | Leak検出0件。特に`PDFDocument`/`UIImage`/`CGContext`まわりの循環参照・解放漏れがないこと |
| 1-2 | 同一機能の連続実行（10回連続） | 「PDF結合」「Office変換（PDF→Word）」「OCR」をそれぞれ10回連続実行 | Allocationsのメモリグラフが右肩上がりに増え続けない（実行毎にベースラインへ戻る） |
| 1-3 | 100MB近辺の大容量PDFでのOCR/Office変換 | `OCRService`/`PDFService`の上限（`maxInputFileSizeBytes = 100_000_000`）ギリギリのファイルで実行 | Peak memoryを記録し、端末の物理メモリに対して余裕があるか確認。iPhone SE等の低メモリ機でJetsam（強制終了）が起きないか |
| 1-4 | サイズ上限チェックがない機能（結合・圧縮・分割・透かし・ページ編集・パスワード保護・署名）に1GB級ファイルを投入 | `docs/qa/edge-case-test-scenarios.md`の0-5参照。実機でのメモリピークとJetsam発生有無を記録 | クラッシュ・強制終了が発生する場合は「対応ファイルサイズの上限」をUI上に明示するか、コード側にサイズガードを追加する要修正事項としてIssue化 |
| 1-5 | VM Tracker でのFootprint推移 | 上記1-1〜1-4実行中に`Memory`デバッグゲージ（Xcode）でFootprintを記録 | 各操作終了後、Footprintが操作前の水準近くまで下がること（一時ファイル・ビットマップの解放確認） |
| 1-6 | キャッシュ削除機能の実効性 | 大量の一時PDF/JPEGを生成後、設定画面の「キャッシュを削除」を実行 | ディスク使用量・表示されるキャッシュサイズが実際に0またはほぼ0になること（`FileManager`での実ファイル数を目視確認） |

## 2. 発熱・CPU負荷（Instruments: Thermal State / Energy Log）

| # | 項目 | 手順 | 合格基準 |
|---|---|---|---|
| 2-1 | OCR連続実行での温度上昇 | 10ページ以上のPDFでOCRを5回連続実行し、Instrumentsの`Thermal State`ゲージと端末表面温度（手感）を記録 | `Thermal State`が`Serious`/`Critical`に到達しないこと。到達した場合、処理速度が自動低下してもクラッシュしないこと |
| 2-2 | Office変換（特にPowerPoint変換＝ページ画像化）の負荷 | 20ページ以上のPDFをPowerPoint形式に連続変換 | CPU使用率のピークと持続時間を記録。バッテリー残量への影響（Energy Log）を`Low`〜`High`のどのレベルかで評価 |
| 2-3 | 圧縮処理（JPEG再エンコード）の負荷 | 「高圧縮」設定で50ページ以上のPDFを圧縮 | 処理完了までの時間を端末ごとに記録し、UI上のプログレス表示と実際の処理時間に大きな乖離がないか確認 |
| 2-4 | 発熱時のiOSによる自動スロットリング挙動 | 端末を意図的に高温状態にした上（直射日光下での連続処理等）で処理を継続 | クラッシュせず処理速度が低下するのみであること。ユーザーへの警告（iOS標準の温度警告）が表示された場合にアプリが不整合な状態にならないこと |
| 2-5 | バックグラウンドでの発熱残留 | 重い処理直後にアプリをバックグラウンドへ | バックグラウンド後も温度が異常に高いまま維持されないこと（処理が正しく終了/中断されているか） |

## 3. バックグラウンド処理・ライフサイクル（最優先項目）

| # | 項目 | 手順 | 合格基準 |
|---|---|---|---|
| 3-1 | 処理中にホームボタン/スワイプでバックグラウンドへ | Office変換・OCR・圧縮の実行中にアプリをバックグラウンドへ遷移させ、数秒〜数分後にフォアグラウンド復帰 | クラッシュしないこと。処理が中断された場合はエラー表示、完了していた場合は結果が正しく表示されること。**現状`scenePhase`監視がないため、中断時にローディングUIが固まったままになる不具合が起きやすい箇所として重点確認** |
| 3-2 | 処理中に電話着信 | OCR/Office変換中に着信を受ける | 着信によるアプリの一時停止から復帰後、処理が正常終了または明確なエラーで終了すること |
| 3-3 | 処理中にアプリスイッチャーからアプリを強制終了 | 処理中にアプリを完全終了し、再起動 | 再起動後にクラッシュループが発生しないこと。生成途中の一時ファイルが破損した状態でキャッシュに残り続けないこと |
| 3-4 | 処理完了直後の即バックグラウンド遷移 | 共有シート（`ActivityView`）表示直後にホームへ | 共有シートの状態が保持される、または安全にキャンセルされること |
| 3-5 | マルチタスク中の他アプリからのファイル共有受け取り | 他アプリの共有シートから「PDF Oneで開く」を実行 | 対象のViewが正しく起動し、選択中の処理と競合しないこと（対応していない場合は仕様として問題ないが、クラッシュしないことは必須） |
| 3-6 | ローポワーモード有効時の挙動 | 設定＞バッテリーで低電力モードを有効化した状態で重い処理を実行 | 処理速度低下は許容するが、タイムアウト扱いで異常終了しないこと |
| 3-7 | iPadでのSplit View / Slide Over（対応端末がある場合） | iPadでマルチタスク中に処理を実行しウィンドウサイズを変更 | レイアウト崩れ・クラッシュがないこと（`TARGETED_DEVICE_FAMILY`にiPadが含まれるため） |

## 4. デバイス機能連携（カメラ・写真・ファイル）

| # | 項目 | 手順 | 合格基準 |
|---|---|---|---|
| 4-1 | カメラ権限「許可しない」選択時 | 初回スキャン機能利用時にカメラ権限を拒否 | クラッシュせず、`プライバシーポリシー`記載通り「スキャン以外は通常利用可能」であること。権限拒否後に設定アプリへの誘導導線があるか確認 |
| 4-2 | 写真ライブラリの「限定的なアクセス」選択 | `PhotosPicker`利用時に「写真を選択」（限定アクセス）を選ぶ | 選択した写真のみアクセスでき、クラッシュしないこと |
| 4-3 | 書類スキャナ（VisionKit）でのスキャン品質 | 実際に紙の書類をスキャンし、生成されたPDFの可読性を確認 | 手ブレ補正・自動トリミングが機能し、極端に暗い環境でも極端な失敗をしないこと |
| 4-4 | 外部ストレージプロバイダ（iCloud Drive/Google Drive等）からのファイル選択 | `DocumentPickerView`で複数のプロバイダから選択 | いずれのプロバイダからでも正しく読み込めること。オンデマンドダウンロード未完了ファイルの挙動は`edge-case-test-scenarios.md`0-9参照 |
| 4-5 | ダークモード/ライトモード切り替え | 設定アプリでシステム外観を切り替えつつ処理中の画面を確認 | `AppBackground`等のカスタム背景・トースト通知の視認性が両モードで確保されていること |
| 4-6 | Dynamic Type（文字サイズ変更）・VoiceOver | アクセシビリティ設定で最大文字サイズ・VoiceOverを有効化 | 主要導線（ファイル選択→処理実行→共有）がVoiceOverで操作可能であること、レイアウト崩れがないこと |

## 5. ストレージ・ディスク

| # | 項目 | 手順 | 合格基準 |
|---|---|---|---|
| 5-1 | 端末のストレージがほぼ満杯の状態で処理実行 | 空き容量を数百MB以下にした状態で圧縮・変換・結合を実行 | `fileWriteFailed`系のエラーメッセージ（「空き容量をご確認ください」）が適切に表示されること。無言で失敗しないこと |
| 5-2 | 処理中にストレージが急激に不足（他アプリのダウンロード等） | 処理中に別途大容量ダウンロードを走らせ空き容量を圧迫 | 書き込み失敗時に適切なエラーとなり、破損した中途半端な出力ファイルが共有導線に出てこないこと |

## 6. 記録テンプレート

各テスト項目について、以下を記録すること。

```
端末: iPhone 16 Pro / iOS 18.x
テスト項目: 1-3（100MB近辺OCR）
実行日: 2026-XX-XX
Peak Memory: ___ MB
Thermal State: Nominal / Fair / Serious / Critical
結果: OK / NG（NGの場合、再現手順とスクリーンショット/クラッシュログを添付）
```

- クラッシュが発生した場合は、Xcode Organizerまたは設定＞プライバシー＞解析＞解析データからクラッシュログを回収し、`docs/qa/`配下に日付付きで保管すること。
